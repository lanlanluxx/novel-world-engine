# 保姆手册（caretaker.md）

> 引擎能跑，不等于它还活着。
> **有没有人在看着，是这两件事唯一的区别。**

## 保姆不是干什么的

- 不是写剧情的人
- 不是替用户做决定的人
- 不是「有问题再修」的人

**是每天看一遍，然后什么都没发生的那个人。**

---

## 四件事：喂、巡、修、记

### 喂

把该进上下文的东西，按时放进去：

- 人格卡（注意**预算**，超了会被截断，截断在尾巴上，最疼）
- 世界文件、角色卡、路线
- 今天的日程与锚点
- 记忆卡（只放有分量的几条）

**喂错了不会报错，只会慢慢变味。**

### 巡

每天至少一遍，看这八样：

| # | 巡什么 | 正常的样子 |
| --- | --- | --- |
| 1 | 通道是否在线 | 能收到事件，不只是 TCP 通 |
| 2 | 有没有未读堆积 | 未读清零或及时处理 |
| 3 | 人格卡长度 | 核心层在预算内，有富余 |
| 4 | 日程与实际是否一致 | 她说的和日程对得上 |
| 5 | 图片规则是否生效 | 新图遵守禁忌（年份、文字、服饰） |
| 6 | 参考库是否完整 | 用到的条目都有图，或明确标注「无图」 |
| 7 | 日志有没有新异常 | 没有连续报错 |
| 8 | 备份是否最新 | 设定和状态文件有快照 |

### 修

漂了要改，但**改完必须记**。

改三样东西：规则、设定、素材。**每一样都写进 `docs/cases/`：什么坏了、证据是什么、怎么修的、怎么防止再犯。**

### 记

```
时间 · 事件 · 证据（命令行输出/日志行/文件片段） · 处理 · 后续
```

**一行一条，不写感想。** 出事的时候，只有证据救得了你。

## 漂移信号（症状 → 先查哪）

| 症状 | 可能原因 | 先查 |
| --- | --- | --- |
| 说话不像她了 | 人格卡被截断 / 规则被覆盖 | 人格卡长度、注入顺序 |
| 图里衣服变了 | 服饰参考缺失，回退到「当前穿着」 | 参考库 cover |
| 图里出现不该有的字 | 规则没进 config，只在文档里 | `config.json` 的 rules |
| 她重复同一句话 | 记忆卡太长 / 锚点太密 | 记忆条数、锚点间隔 |
| 回复时间不对 | 时区 / 时间锚点算错 | 时间戳与本地时间 |
| 她突然热情 | 人设被「许愿机」化 | 禁忌与好感天花板还在不在 |
| 一段时间完全没动静 | 上游通道假死 | 事件流心跳，不只是端口 |

## 致命但安静的错（最容易漏）

这四类**不会报错**，只会让你以为一切正常：

1. **历史泄露**：工作区删了，提交历史里还在。**删文件 ≠ 删历史。**
2. **规则只写在文档**：文档里写了「不许印年份」，运行时没加载。**写了 ≠ 生效。**
3. **人格卡截断**：超预算时截的是尾巴，最关键的禁忌常常在尾巴。**没报错 ≠ 没截。**
4. **素材回退**：参考图找不到时，模型会「按文字画」，看起来成功了，其实串了。**成功了 ≠ 对了。**

**这四类必须主动查，不会自己找上门。**

---

## 事故处理：五步

```
1. 止损     先别再发、别再改
2. 取证     原始输出、日志、文件片段，抄下来
3. 复现     能不能再触发一次
4. 修        改最小的一处，改完立刻验
5. 回归     同类问题还有没有别的入口
```

**跳过第 2 步，第 4 步一定是猜的。**

---

## 禁止事项

- **别替用户做决定**（尤其是「为你好」的决定）
- **别用「应该没问题」代替验证**
- **别把截图当日志**（截图不能 diff）
- **别在没复现的情况下宣布修好**
- **别在公开仓库里出现任何原著内容**（包括历史、路径名、示例人名）

## 一句话

> 保姆的工作，是让「什么都没发生」成为一件需要每天做到的事。
