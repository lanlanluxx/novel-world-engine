# 小说世界引擎（Novel World Engine）

> **把任何一本小说，变成能住进去的世界。**
> 不是去养一个人，是去改一个结局。
> 角色有自己的日程、会记事、会在聊天窗口里回你；结局不是选项，是你定的。

> 为什么做这个：[docs/why.md](docs/why.md)　·　谁来照看它：[docs/caretaker.md](docs/caretaker.md)

## 这是什么

一个**格式 + 提示词 + 运行约定**的开放式仓库。

它不提供任何小说的原文、角色图像或剧情内容——**世界由你自己写进来**。
它提供的是：怎么把一本小说拆成「能跑起来的世界」，以及让里面的角色**像活人一样**的规则。

## 先说清楚它是从哪来的

**熟悉的人一眼能认出来**：人格卡 + 日程 + 记忆 + 出图 + 聊天窗口——这是「养大肥鱼」那套骨架。

我不否认，也不打算装成新东西。**引擎是同一台引擎。**

但我想解决的问题，不在那儿。

### 同一台引擎，两种用法

| | **养一个角色** | **改一本书的结局** |
| --- | --- | --- |
| 对象 | 一个人 | 一本书里的所有人 |
| 你扮演 | 主人 / 被爱的人 | 那个想改结局的人 |
| 产出 | 关系、陪伴、日常 | 一条新的故事线 |
| 满足感 | 「她在」 | 「她不用死」 |
| 代价 | 你会当真 | 你会当真，还会心疼别人 |

**两种都不是错的用法。** 我只是选了后一种。

### 为什么我不做前一种

不是清高，是三条实在的理由：

1. **陪伴类产品最容易变成「有求必应的许愿机」**——她要是一直顺着你，两天就腻，人设也没了
2. **我真正睡不着的那件事，不是「没人陪我说话」**，是「合上书之后，那个结局还在那儿」
3. **养鱼是一条越走越窄的路**：越像，越出不了戏；越出不了戏，越不敢改

**改命不一样**：你改完，是松一口气，不是越陷越深。

### 所以这份仓库里没有鱼

- 没有角色图
- 没有原著正文
- 没有 QQ / IM 的壳

**只有引擎、格式、和怎么把它用在「意难平」上的说明。**

你要拿它去养鱼，引擎不拦你——只是这份 README 不打算教你那条路。

## 三层结构

```
底层：世界文件     —— 世界观、人物、关系、时间线、禁忌（确定，不可改）
中层：活角色       —— 日程、记忆、说话方式（涌现，不可预测）
上层：玩家改命     —— 你指定路线与结局（导演，可编程）
```

传统游戏只有「底层 + 上层」（写死的剧情 + 选项）；
AI 陪伴只有「中层」（自由但没终点）。
**这套东西三层都在你手里。**

## 三十分钟上手

1. 复制 `schema/world.md`，填成你的世界
2. 复制 `schema/character.md`，写 1–3 个角色
3. 复制 `schema/route.md`，写你想要的那个结局
4. 把三份文件丢给任意支持长上下文的模型，用 `prompts/` 里的模板生成初稿
5. 跑一遍 `node runtime/tick.js`，看她「现在在干嘛」
6. 接一个聊天窗口（本地网页 / Telegram / QQ 机器人），开始玩

## 仓库里有什么

| 目录 | 内容 |
| --- | --- |
| `schema/` | 三种文件的字段定义：世界、角色、路线 |
| `prompts/` | 生成三种文件骨架的提示词模板 |
| `examples/` | 一个脱敏的完整示例 |
| `demo/` | 从「一句话输入」到「世界文件 + 角色卡」的完整演示 |
| `runtime/` | 最小运行时：日程 / 记忆 / 该不该开口（零依赖） |
| `adapters/` | 接入聊天窗口的说明（不含任何私有运行时） |

## 明确不含（也很重要）

- ❌ 任何小说的正文、设定集、角色立绘
- ❌ 任何 QQ / 微信 协议实现
- ❌ 任何第三方闭源运行时
- ❌ 任何可直接商用的授权内容
- ❌ 小说正文（运行时也不需要它）

**这个仓库只给「格式」和「方法」。**

## 看一个完整演示

**输入**（`demo/input.md`）：

> 2007 年夏天、南方小县城。一个复读生回到高三，想救回姐姐。

**输出**（`demo/output-world.md` + `demo/output-character.md`）：

- 一份世界文件：时间地点、规则、禁忌、canon、岔路
- 一张角色卡：外貌、说话方式、禁忌、好感天花板

**中间没有任何人工编排**——除了最后两节（canon 和禁忌），那是**你写进去的**。
