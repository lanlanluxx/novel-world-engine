# 路线与结局（route.md）

> **你不是选结局，你是在写结局——然后看角色自己走过去。**

## 格式

```markdown
# 路线：<一句话目标>

## 结局契约
- 我想要的结局（一句话）：
- 绝对不能出现的结局：
- 可以接受的折中：

## 阶段
1. <第 1 段>：从哪到哪
2. <第 2 段>：中间发生了什么
3. <第 3 段>：怎么收

## 意图（不是指令）
- 让她开始怀疑：
- 让他主动一次：
- 让两个人的关系被第三方撞破：

## 角色可以抵抗的地方
- 她可能不做：
- 他可能拒绝：
- 如果抗拒，就顺着写（这不是失败）

## 判定
- 走到结局的标志：
- 走偏的标志：
```

## 为什么写“意图”而不是“指令”

| 写法 | 效果 |
| --- | --- |
| ❌「第 5 章她要主动表白」 | 角色变成执行器，戏没了 |
| ✅「这一章让她忍不住靠近一点」 | 她怎么靠近，是她的自由 |

**指令写的是动作，意图写的是方向。**

## 「角色可以抵抗」这一节必须写

**这是最容易忽略、也最值钱的一节。**

角色有自己的性格，你的路线她可能不走。这时候：

- 顺着写 → 你得到一个**更真实**的故事
- 强行压回去 → 你得到一个**听话的娃娃**

**写清楚“她可能会怎么抗拒”，你就知道该往哪写。**

## 结局契约

写清三样：

1. **想要的**（一句话）
2. **绝对不要的**（防止 AI 走歪）
3. **可接受的折中**（给它发挥空间）

## 多条路线

同一个世界可以开多条路线：

```
route-a.md  救下她
route-b.md  让他们在一起
route-c.md  自己和她在一起
```

**每条路线独立成文件，互不覆盖。**
